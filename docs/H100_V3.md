# H100: validate v3, then run the frozen follow-up

Dated 2026-10-22. These are new runs, not a continuation of
`results-qwen3-v2`. The uploaded v2 snapshot is preserved at `73f2ba1`.
It contains 205 records, ten harness passes and seven complete 27-cell bugs.
It does not establish an IR-aware repair improvement. Reproduce its audit
without depending on the working results directory:

```bash
python3 scripts/report_snapshot.py --snapshot 73f2ba1
```

## 1. Stop at a cell boundary and update

Let the current cell finish, then stop the repair runner before updating
code. Keep completed v2 JSON files. Only one repair or known-patch validation
process may use the LLVM checkout at a time. The model server can stay
running while Git and read-only analyses run. Check existing tmux sessions
with `tmux ls` before creating another runner.

```bash
git switch feat/h100-sweep
git pull --ff-only
source venv/bin/activate
```

Use the environment file from your existing H100 setup to retain
`LAB_DATASET_DIR`, `LAB_LLVM_DIR`, `LAB_LLVM_BUILD_DIR` and
`LAB_LLVM_ALIVE_TV`. Keep the benchmark dataset and cached builds. Do not run
`git reset --hard`, delete result manifests, or use `--overwrite` to bypass
a configuration mismatch. Do not pull new code into a running sweep.

## 2. Pin and record the Qwen server

If the active server's exact weight revision and invocation were recorded,
retain them. Otherwise restart the server once with a known revision. In the
**vLLM environment**, resolve a revision and preserve the literal SHA:

```bash
source ~/vllm-venv/bin/activate
mkdir -p run-provenance
python3 - <<'PY' > run-provenance/qwen-revision.txt
from huggingface_hub import model_info
print(model_info('Qwen/Qwen3-Coder-30B-A3B-Instruct').sha)
PY
export LAB_LLM_MODEL_REVISION="$(cat run-provenance/qwen-revision.txt)"
python3 -m pip freeze > run-provenance/vllm-packages.txt
nvidia-smi > run-provenance/gpu.txt
```

Resolve this once, before the pilot. Keep the same file throughout v3. Do not
replace its SHA with a newer branch tip on resume. Resolving the current
revision may download weights if they are not already cached. The command
below retains the previously used FP8 quantization and memory limit; it is
not a measured speed improvement. Save it as the server's invocation receipt.

```bash
export VLLM_USE_FLASHINFER_SAMPLER=0
vllm serve Qwen/Qwen3-Coder-30B-A3B-Instruct \
    --revision "$LAB_LLM_MODEL_REVISION" \
    --tokenizer-revision "$LAB_LLM_MODEL_REVISION" \
    --served-model-name qwen3-coder-30b \
    --quantization fp8 \
    --max-model-len 32768 \
    --gpu-memory-utilization 0.55 \
    --enforce-eager \
    --host 127.0.0.1 --port 8000 \
    --api-key local-sweep 2>&1 | tee run-provenance/qwen-server.log
```

Run this in a dedicated tmux session, for example `tmux new -s qwen-server`.
Wait for successful startup. A tmux session survives SSH loss but cannot
survive a container restart; the resumable result records handle that case.

In a second shell, activate the **repair environment** and set:

```bash
source venv/bin/activate
export LAB_LLM_URL=http://127.0.0.1:8000/v1
export LAB_LLM_TOKEN=local-sweep
export LAB_LLM_MODEL=qwen3-coder-30b
export LAB_LLM_TEMP=0.8
export LAB_LLM_MAX_TOKENS=8192
export LAB_LLM_MODEL_REPOSITORY=Qwen/Qwen3-Coder-30B-A3B-Instruct
export LAB_LLM_MODEL_REVISION="$(cat run-provenance/qwen-revision.txt)"
export LAB_LLM_SERVING_ID="qwen-fp8-32k-mem055-eager-v3-$(sha256sum run-provenance/vllm-packages.txt | cut -d' ' -f1)"
git rev-parse HEAD > run-provenance/source-commit.txt
python3 -m pip freeze > run-provenance/repair-packages.txt
sha256sum "$LAB_LLVM_ALIVE_TV" > run-provenance/alive-tv.sha256
python3 scripts/check_llm_endpoint.py --repair-format --repeat 3
```

The serving ID describes this recorded invocation; retain it on resume. Save
the command, server log, package list, GPU report, Git commit and repair
environment's `pip freeze` with the final archive. Do not archive credentials.
If the endpoint check fails, fix the server or format before building LLVM.
This small prompt checks transport and edit format, not repair ability or
sampling diversity. A null `model_revision` in the protocol is explicitly
unknown; the environment above supplies the actual pinned revision to records.

## 3. Known-patch validation, then a six-run pilot

First verify the unpatched reproducer fails semantically and the human repair
passes the same validation harness, on excluded development bug `115575`:

```bash
python3 scripts/check_validation.py --bug-id 115575 --build-jobs 64
```

Require `PASS`. Inspect the diagnostic JSON if it fails. A build crash,
timeout, missing plugin or a reproducer that already passes is an
infrastructure problem, not a negative model result.

Then run **six pilot cells**, one trial each, with the same v3 settings:

```bash
python3 examples/repair_experiment.py 115575 \
    --repeat 1 --max-iterations 4 --oracle-budget 400 \
    --build-jobs 64 --out results-qwen3-v3-pilot \
    --condition baseline raw-plain generic-plain llvmreduce-plain \
                iraware-plain iraware-structured

python3 scripts/triage_sweep.py results-qwen3-v3-pilot
python3 scripts/inspect_patches.py results-qwen3-v3-pilot
python3 scripts/audit_sweep.py results-qwen3-v3-pilot --repeat 1 \
    --condition baseline raw-plain generic-plain llvmreduce-plain \
                iraware-plain iraware-structured
```

Review every malformed/truncated edit, baseline build failure, verifier
fallback, unexpected linker failure and regression-stage tool error. At
least one actual patch should pass the full listed validation on this
previously repairable development bug before committing the remaining budget.
One successful pilot does not establish method superiority. If it fails,
preserve its records and diagnose; do not repeatedly tune on evaluation bugs.
Pilot time gives a rough scheduling reference, but different base commits can
require much slower builds. No trustworthy completion ETA is available yet.

## 4. Run the amended protocol: 288 cells

The JSON fixes 16 bugs, six conditions, three trials, four turns and all four
original primary contrasts. These are the two remaining preselected size
tiers, not a pristine unseen test set: `115149` had earlier diagnostic
exposure. No v2 cells are reused. The amendment and limitations are recorded
in `docs/ANALYSIS_PLAN.md` and the paper.

```bash
python3 examples/repair_experiment.py \
    --protocol data/repair_v3_protocol.json \
    --build-jobs 64 --out results-qwen3-v3 --plan
```

The plan should show **288 runs**. It makes no model calls and does not build.
After the checks above pass, start a tmux runner (`tmux new -s repair-v3`) and
run:

```bash
python3 examples/repair_experiment.py \
    --protocol data/repair_v3_protocol.json \
    --build-jobs 64 --out results-qwen3-v3
```

After interruption, restore the same environment and rerun that identical
command. Completed compatible cells are skipped; endpoint-error records are
retried. If it reports a different harness/model/budget, inspect the recorded
configuration. Do not delete `.experiment.json` or change `--out` merely to
evade the guard. A real change starts a separately named experiment.

Reduce build jobs only if memory pressure requires it, consistently documenting
the change. Do not change prompts, reduction budgets, weights or generations
mid-sweep. Do not increase repeats or omit bugs in response to outcomes.

## 5. Analyze and share the completed data

Read-only monitoring is safe alongside the sole repair process:

```bash
python3 scripts/triage_sweep.py results-qwen3-v3
python3 examples/summarize_results.py results-qwen3-v3 \
    --protocol data/repair_v3_protocol.json
```

After all 288 records exist, require the final analysis completion guard:

```bash
python3 examples/analyze_significance.py results-qwen3-v3 \
    --protocol data/repair_v3_protocol.json --final
```

Share the pilot, main run JSONs (including `.experiment.json`), validation
diagnostics and provenance. These output folders are ignored by default;
explicitly stage only the reviewed files when archiving them. Do not mix v2
and v3 outcomes or describe selected test passes as semantic proof. Review
passing patches for overbroad optimization suppression and additional corner
cases before calling them correct repairs.

The optional independent-model pilot is in [MODEL_FOLLOWUP.md](MODEL_FOLLOWUP.md).

on this H100, and no claim that it improves LLVM repairs is made.
